---
title: "Agents"
description: "Authorize a trading client without giving it custody."
---

A Cinder agent is a separate Ed25519 key that you authorize to act on your private account. It is not a native venue agent and never receives Cinder's pooled execution keys.

Use an agent for a bot or trading application that should not require a wallet prompt for every action. The client keeps its agent private key; the account owner signs a grant for that key's public address.

## Permissions

The owner creates a [grant](/api/methods/grant) with an expiry, permissions and order limits.

| Permission | Access |
| --- | --- |
| READ | Read the bound account's balances, positions, operations and history across markets. The grant's market does **not** restrict READ to that market. |
| TRADE | Place orders in the grant's market, subject to per-order size and fee limits and a lifetime accepted-order budget. |
| CANCEL | Cancel orders admitted under that agent's key in the grant's market. It cannot cancel the owner's or another agent's orders. |

The agent-grant directory shows an agent only its own active grant, not other agents' keys. An account owner can see the account's grant directory.

<Warning>
READ exposes account information across markets. Grant it only to clients you trust with that information.
</Warning>

Agents cannot withdraw funds, change recipients, select leverage, authorize another agent or administer Cinder.

An order budget counts accepted orders, not fills or calendar days. With a budget of 10, one accepted order that fills in several parts consumes one slot. Retrying that same order does not consume another slot; a new accepted order does.

Each grant authorizes trading and cancellation in one market. Trading multiple markets requires separate scoped agent keys. A grant cannot be edited in place within the same authority epoch; changing those permissions requires account-wide revocation and explicit new grants.

## Revocation

<Warning>
Revocation disables all existing agent grants for the account. It does not automatically cancel outstanding orders.
</Warning>

[Revoke](/api/methods/revoke) advances the account's authority epoch. Requests signed under the previous epoch lose authority, including requests from previously authorized agents.

The owner must cancel or reconcile outstanding orders separately. Use the current epoch for subsequent requests and explicitly grant any agent that should regain access.
