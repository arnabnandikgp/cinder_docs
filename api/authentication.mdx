---
title: "Authentication and signing"
description: "Wallet or agent signatures bound to a verified encrypted session."
---

The account owner signs with their Solana wallet. An authorized [agent](/guides/agents) signs with its own Ed25519 key. Neither signer receives Cinder's venue credentials.

## Request envelope

| Field | Type and meaning |
| --- | --- |
| `domain.network`, `domain.deployment` | Nonzero 32-byte identifiers for the configured Cinder environment and logical deployment, not numeric blockchain chain IDs. |
| `account` | Your configured nonzero 32-byte private account ID, not your wallet or a pooled venue account. |
| `id` | Nonzero 32-byte request ID. Preserve it for the same economic intent. |
| `policy` | The approved nonzero u32 financial/precision policy revision, not the SDK version. |
| `epoch` | The account's current positive u64 authorization generation; revocation advances it. |
| `signer` | The owner or currently authorized agent's Ed25519 public key. |
| `session` | Verified channel binding, supplied by the SDK. |
| `expiresAt` | Authentication expiry timestamp in milliseconds, within channel and configured authentication limits; not the order's financial deadline. |
| `command` | The exact typed command. |
| `signature` | A 64-byte Ed25519 signature over the SDK's canonical signing message. |

The client uses the supplied domain, account and policy configuration; the verified channel supplies the session binding. Each `request` supplies `id`, `epoch`, `expiresAt` and `command`. See [SDK integration](/quickstart) for the configuration inputs and their sources. Neither an account ID nor a guessed configuration value grants access.

## Attestation and signing

Before a private request, the SDK verifies the AWS attestation chain, approved enclave measurements and release manifest, deployment identity, fresh challenge, channel key and session expiry.

Code and expected release identity must come from trusted distribution, independently of the relay being verified.

Requests use the `CINDER-API\0\x00\x01` fixed-width big-endian signing format. Signing a displayed JSON object or a native venue payload is not equivalent.

## Authority and retries

Current signatures, grant permissions, authority epoch and journal freshness are checked before lookup or replay. Revocation changes the epoch and disables previous grants.

The economic identity binds the domain, account, request ID, policy and exact command. In particular, changing `goodUntil` changes the intent. A fresh session may re-sign the same intent with a new authentication expiry; it does not create permission for another external attempt.

READ agents can view the bound account across markets. TRADE and CANCEL retain their market and order restrictions. See [agent permissions](/guides/agents) and [reconciliation](/api/lifecycle).
