**Carrier:** `POST /v1/exchange` (encrypted binary).

**Read family:** `movements` · **Permission:** owner or current READ agent.

Changes to your recorded cash, funding and positions. Results belong to your account. The query supports HTTP and
[WebSocket](/api/websocket), including subscriptions.

<Note>Examples show [SDK values](/api/overview), not a plaintext HTTP JSON body.</Note>

<RequestExample>
```ts SDK request
const response = await client.request({
  id: ctx.id,
  epoch: ctx.epoch,
  expiresAt: ctx.expiresAt,
  command: {
    kind: 'read',
    query: { family: 'movements', limit: 32 },
  },
});
```
</RequestExample>

<ResponseExample>

## Request fields

Use the configured [client and envelope](/api/authentication). Each request supplies
`id`, current `epoch` and authentication `expiresAt`, as shown in the example.

<ParamField body="command.kind" type="&quot;read&quot;" required>
  Read-command discriminator.
</ParamField>

<ParamField body="command.query.family" type="&quot;movements&quot;" required>
  Selects this exact private projection.
</ParamField>

<ParamField body="command.query.limit" type="number" required>
  Integer from 1 to 64 rows. The example requests 32.
</ParamField>

<ParamField body="command.query.cursor" type="Uint8Array (40 bytes)">
  Omit or use all-zero bytes to start. For another page, use the prior page’s `next` under the same snapshot revision.
</ParamField>

## Behavior

Includes applied operator or forced changes, fees, funding and receipts that change the customer book. Compound changes are not mislabeled as deposits. Holds or pool treasury moves without a customer book change are not cash postings. The index derives from authoritative commit/replay; it is not an editable second ledger.

## Paging and errors

See [paging](/api/reads/paging) for cursors, revisions and missing values, and
[errors](/api/errors) for response codes. Reconnect and fetch a new snapshot after
a subscription closes.
