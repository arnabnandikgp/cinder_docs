**Carrier:** `POST /v1/exchange` (encrypted binary).

**Read family:** `movements` · **Permission:** owner or current READ agent.

Changes to your recorded cash, funding and positions. Results belong to your account. The query supports HTTP and
[WebSocket](/api/websocket), including subscriptions.

<Note>Configure `client` and the example inputs using [SDK integration](/quickstart). Examples show typed SDK values, not a plaintext HTTP JSON body.</Note>

<RequestExample>
```ts SDK request
const response = await client.request({
  id: ctx.id,
  epoch: ctx.epoch,
  expiresAt: ctx.expiresAt,
  command: {
    kind: 'read',
    query: { family: 'movements', limit: 32 },
  },
});
```
</RequestExample>

<ResponseExample>
```ts Decoded page
({
  kind: 'page',
  family: 'movements',
  revision: snapshotRevision,
  next: new Uint8Array(40),
  evaluatedAt: observedAt,
  rows: [
    {
      kind: 'movement', committedAt: observedAt,
      before: { cash: 100n, funding: 0n, positions: [] },
      after: { cash: 99n, funding: 0n, positions: [] },
    },
  ],
})
```

```ts Stale cursor error
({ kind: 'error', code: 'conflict' })
```
</ResponseExample>

## Request fields

Use the configured [client and envelope](/api/authentication). Each request supplies
`id`, current `epoch` and authentication `expiresAt`, as shown in the example.

<ParamField body="command.kind" type="&quot;read&quot;" required>
  Read-command discriminator.
</ParamField>

<ParamField body="command.query.family" type="&quot;movements&quot;" required>
  Selects this account-data family.
</ParamField>

<ParamField body="command.query.limit" type="number" required>
  Integer from 1 to 64 rows. The example requests 32.
</ParamField>

<ParamField body="command.query.cursor" type="Uint8Array (40 bytes)">
  Omit or use all-zero bytes to start. For another page, use the prior page’s `next` under the same snapshot revision.
</ParamField>

## Behavior

Use `before` and `after` to see how a recorded event changed your cash, unsettled funding or positions. Rows can include fees, funding settlement, confirmed payments, liquidation and other applied account adjustments.

A single event can change several values. For example, funding settlement changes both cash and unsettled funding; do not classify every cash increase as a deposit. The response does not include a separate event-type label.

Changes only to reservations or transfers of pooled collateral that leave your recorded cash, funding and positions unchanged do not create a movement row. See [account reads](/api/reads/account) for reservations and [operations](/api/reads/operations) for request progress.

## Paging and errors

See [paging](/api/reads/paging) for cursors, revisions and missing values, and
[errors](/api/errors) for response codes. Reconnect and fetch a new snapshot after
a subscription closes.
