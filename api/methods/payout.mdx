**Carrier:** `POST /v1/exchange` (encrypted binary).

**Permission:** Owner only.

Request a withdrawal to your configured recipient. The same command is available over [WebSocket](/api/websocket).

<Note>Examples show [SDK values](/api/overview), not a plaintext HTTP JSON body.</Note>

<RequestExample>
```ts SDK request
const response = await client.request({ id: ctx.id, epoch: ctx.epoch, expiresAt: ctx.expiresAt,
    command: { kind: 'payout', net: 100n, maximumFee: 1n,
      allowPartial: false, goodUntil: ctx.goodUntil } });
```
</RequestExample>

## Request fields

The client supplies the configured domain, account, policy, signer and verified
session binding, and signs the canonical [envelope](/api/authentication).

<ParamField body="id" type="Uint8Array (32 bytes)" required>
  Nonzero private request ID. Retain it for an exact retry; use a distinct ID for a different intent.
</ParamField>

<ParamField body="epoch" type="bigint (u64)" required>
  Current account authority epoch.
</ParamField>

<ParamField body="expiresAt" type="bigint (u64)" required>
  Authentication expiry in milliseconds, within the verified session and deployment limits.
</ParamField>

<ParamField body="command.kind" type="&quot;payout&quot;" required>
  Command discriminator.
</ParamField>

<ParamField body="command.net" type="bigint (i128)" required>
  Positive net recipient quote atoms, excluding extra fees.
</ParamField>

<ParamField body="command.maximumFee" type="bigint (i128)" required>
  Nonnegative maximum additional customer-paid rail fee. `net + maximumFee` must fit i128.
</ParamField>

<ParamField body="command.allowPartial" type="boolean" required>
  Explicit consent to deliberately partial dispatch.
</ParamField>

<ParamField body="command.goodUntil" type="bigint (u64)" required>
  Financial dispatch expiry in milliseconds.
</ParamField>

## Response fields

The result uses the shared [receipt fields](/api/lifecycle#shared-receipt-fields).
The fields below are most relevant to this method.

<ResponseField name="kind" type="&quot;receipt&quot;" required>
  Response discriminator.
</ResponseField>

<ResponseField name="id" type="Uint8Array (32 bytes)" required>
  Durable operation ID. For an operation lookup, this is the target ID, not the query ID.
</ResponseField>

<ResponseField name="outcome" type="Outcome" required>
  `rejected`, `accepted`, `dispatched`, `acknowledged`, `partial`, `complete` or `unknown`. See [lifecycle](/api/lifecycle).
</ResponseField>

<ResponseField name="paid" type="bigint (i128)" required>
  Confirmed net payment to the configured recipient, in quote atoms.
</ResponseField>

<ResponseField name="railFees" type="bigint (i128)" required>
  Actual customer-paid payout rail fees; not ordinary trading fees.
</ResponseField>

<ResponseField name="feeCap" type="bigint (i128)" required>
  Declared fee cap: absolute requested lots × fee-per-lot for orders, or extra rail-fee cap for payouts. Not the amount charged.
</ResponseField>

<ResponseField name="possiblyExposed" type="boolean" required>
  Whether the operation may have escaped for external execution. False alone is not a final settlement guarantee.
</ResponseField>

<ResponseField name="allowPartial" type="boolean" required>
  The recorded payout partial-dispatch consent. False for unrelated commands.
</ResponseField>

## Behavior

The request reserves `net + maximumFee`. `paid` records confirmed net payment to your configured recipient; `railFees` records charged withdrawal-transfer fees; `feeCap` is the additional fee limit you authorized.

A withdrawal is complete only after payment to your configured recipient has been confirmed. Acceptance or money leaving a source account is not payment completion. Check `paid` against the requested net amount, especially when partial payment was allowed.

Free collateral can be withdrawn while positions remain open, subject to margin, pending operations and accessible vault funds. Agents cannot request payouts, and the command cannot override your recipient. See [funds](/guides/funds) for the full flow.

## Errors and reconciliation

See [errors](/api/errors) for response codes and [lifecycle](/api/lifecycle)
for delivery failures, receipts and retries. Keep the original operation ID when
reconciling an uncertain result.
