**Carrier:** `POST /v1/exchange` (encrypted binary).

**Permission:** Owner, or CANCEL agent for its own order.

Cancel an order and account for concurrent fills. The same command is available over [WebSocket](/api/websocket).

<Note>Configure `client` and the example inputs using [SDK integration](/quickstart). Examples show typed SDK values, not a plaintext HTTP JSON body.</Note>

<RequestExample>
```ts SDK request
const response = await client.request({ id: ctx.id, epoch: ctx.epoch, expiresAt: ctx.expiresAt,
    command: { kind: 'cancel', target: ctx.originalOrderId,
      attempt: ctx.cancelAttemptId, goodUntil: ctx.goodUntil } });
```
</RequestExample>

## Request fields

The client supplies the configured domain, account, policy, signer and verified
session binding, and signs the canonical [envelope](/api/authentication).

<ParamField body="id" type="Uint8Array (32 bytes)" required>
  ID for this cancellation request, distinct from the original order ID. Retain it for an exact retry.
</ParamField>

<ParamField body="epoch" type="bigint (u64)" required>
  Current account authority epoch.
</ParamField>

<ParamField body="expiresAt" type="bigint (u64)" required>
  Expiry timestamp in milliseconds, within the verified channel and configured authentication limits; not a validity duration.
</ParamField>

<ParamField body="command.kind" type="&quot;cancel&quot;" required>
  Command discriminator.
</ParamField>

<ParamField body="command.target" type="Uint8Array (32 bytes)" required>
  Original Cinder order request ID. It is not a venue order ID or this cancellation request ID.
</ParamField>

<ParamField body="command.attempt" type="Uint8Array (32 bytes)" required>
  Stable cancellation-attempt ID for the target order. Preserve it on retry; it is a different identifier role from the API request ID.
</ParamField>

<ParamField body="command.goodUntil" type="bigint (u64)" required>
  Financial cancellation deadline in milliseconds.
</ParamField>

## Response fields

The result uses the shared [receipt fields](/api/lifecycle#shared-receipt-fields).
The fields below are most relevant to this method.

<ResponseField name="kind" type="&quot;receipt&quot;" required>
  Response discriminator.
</ResponseField>

<ResponseField name="id" type="Uint8Array (32 bytes)" required>
  ID of this recorded command, matching the request's `id`.
</ResponseField>

<ResponseField name="outcome" type="Outcome" required>
  `rejected`, `accepted`, `dispatched`, `acknowledged`, `partial`, `complete` or `unknown`. See [lifecycle](/api/lifecycle).
</ResponseField>

<ResponseField name="filled" type="bigint (i64)" required>
  Actual signed fills on the target order, not quantity cancelled or the original requested size.
</ResponseField>

<ResponseField name="possiblyExposed" type="boolean" required>
  Whether an action or signature may have reached external execution. This is not confirmation of a fill or payment.
</ResponseField>

## Behavior

### Cancellation IDs

| Field | Identifies |
| --- | --- |
| `id` | This API cancellation request. It is distinct from the original order's request ID. |
| `command.target` | The original Cinder order request ID, not a venue order ID. |
| `command.attempt` | The cancellation execution attempt associated with the target. It is a separate identifier from the API request ID. |

Keep all three values, and the exact deadline, unchanged when resubmitting the same cancellation. Changing them describes a different intent or attempt.

### Cancellation and late fills

An order that has not reached external execution can release its local reservation. An exposed order requires cancellation and execution-history reconciliation.

A cancellation acknowledgement does not prove that no late fill can arrive. Query this cancellation's `id` for its progress and the original order's `target` for its final result. There is no raw venue cancel-all command.
