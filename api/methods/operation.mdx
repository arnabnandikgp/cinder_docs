**Carrier:** `POST /v1/exchange` (encrypted binary).

**Permission:** Owner or current READ agent.

Look up a recorded operation and its current status. The same command is available over [WebSocket](/api/websocket).

<Note>Configure `client` and the example inputs using [SDK integration](/quickstart). Examples show typed SDK values, not a plaintext HTTP JSON body.</Note>

<RequestExample>
```ts SDK request
const response = await client.request({ id: ctx.id, epoch: ctx.epoch, expiresAt: ctx.expiresAt,
    command: { kind: 'operation', target: ctx.originalOrderId } });
```
</RequestExample>

<ResponseExample>
```ts Decoded receipt
({
  kind: 'receipt',
  id: ctx.originalOrderId,
  digest: recordedIntentDigest,

  railFees: 0n,

  allowPartial: false,

```

```ts Encrypted application error
({ kind: 'error', code: 'unauthorized' })
```
</ResponseExample>

## Request fields

The client supplies the configured domain, account, policy, signer and verified
session binding, and signs the canonical [envelope](/api/authentication).

<ParamField body="id" type="Uint8Array (32 bytes)" required>
  ID for this lookup request. The response receipt uses command.target as its operation ID.
</ParamField>

<ParamField body="epoch" type="bigint (u64)" required>
  Current account authority epoch.
</ParamField>

<ParamField body="expiresAt" type="bigint (u64)" required>
  Expiry timestamp in milliseconds, within the verified channel and configured authentication limits; not a validity duration.
</ParamField>

<ParamField body="command.kind" type="&quot;operation&quot;" required>
  Command discriminator.
</ParamField>

<ParamField body="command.target" type="Uint8Array (32 bytes)" required>
  Original operation ID in this account, not native order ID or query ID.
</ParamField>

## Response fields

The result uses the shared [receipt fields](/api/lifecycle#shared-receipt-fields).
The fields below are most relevant to this method.

<ResponseField name="kind" type="&quot;receipt&quot;" required>
  Response discriminator.
</ResponseField>

<ResponseField name="id" type="Uint8Array (32 bytes)" required>
  ID of the target operation (`command.target`), not this lookup request's ID.
</ResponseField>

<ResponseField name="outcome" type="Outcome" required>
  `rejected`, `accepted`, `dispatched`, `acknowledged`, `partial`, `complete` or `unknown`. See [lifecycle](/api/lifecycle).
</ResponseField>

<ResponseField name="filled" type="bigint (i64)" required>
  Actual attributed signed lots, not requested quantity.
</ResponseField>

<ResponseField name="paid" type="bigint (i128)" required>
  Confirmed net payment to the configured recipient, in quote atoms.
</ResponseField>

<ResponseField name="railFees" type="bigint (i128)" required>
  Actual customer-paid payout rail fees; not ordinary trading fees.
</ResponseField>

<ResponseField name="feeCap" type="bigint (i128)" required>
  Declared fee cap: absolute requested lots × fee-per-lot for orders, or extra rail-fee cap for payouts. Not the amount charged.
</ResponseField>

<ResponseField name="possiblyExposed" type="boolean" required>
  Whether an action or signature may have reached external execution. This is not confirmation of a fill or payment.
</ResponseField>

<ResponseField name="allowPartial" type="boolean" required>
  The recorded payout partial-dispatch consent. False for unrelated commands.
</ResponseField>

## Behavior

The result is the current [receipt](/api/lifecycle) for `command.target`. Its `id` is the target operation's ID, not this lookup request's ID. The target can be an order, cancellation, payout or other recorded command.

### If lookup returns not-found

`not-found` means the authorized lookup found no matching record in this account. It does not, by itself, establish the outcome of an earlier uncertain delivery.

1. Check the original account, deployment and request ID.
2. Retain the original command and any acknowledgement or receipt.
3. Ask the service operator to reconcile the account and external venue history if execution is still uncertain.
4. Wait for the outcome to be established before another execution attempt.

Changing the request ID can cause duplicate execution. The lookup itself does not resend the target.

## Errors and reconciliation

See [errors](/api/errors) for response codes and [lifecycle](/api/lifecycle)
for delivery failures, receipts and retries. Keep the original operation ID when
reconciling an uncertain result.
