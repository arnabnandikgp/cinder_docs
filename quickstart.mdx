This guide is for developers integrating a trading application or automated client with Cinder. It connects an existing Cinder account and returns its compact account view. Connecting a wallet authenticates that account; it does not create an account or deposit funds.

Traders using an application do not enter these values manually. The application supplies the client configuration and asks their wallet to sign requests.

## Before you begin

Obtain three sets of inputs before running the example:

1. **Service configuration and SDK bundle:** the API address, network and deployment IDs, and matching SDK files from the Cinder service operator or your application's integration maintainer.
2. **Trusted release policy:** the expected manifest hash and enclave measurements from an independently approved release. These values tell the client which enclave release to accept.
3. **Existing account configuration:** your private account ID, applicable policy version, current authority epoch and permitted authentication lifetime, together with an owner wallet or authorized agent signer.

This page does not provide a public API hostname, SDK download URL or account-registration endpoint. Obtain the inputs for the service you intend to use rather than inventing IDs or treating the examples as connection credentials. You do not need to deploy an enclave or configure AWS to use the client.

## Prerequisites

| Input | What it means | Where to obtain it |
| --- | --- | --- |
| `sdk.js`, `channel.js`, `channel_bg.wasm` | The client interface, JavaScript bindings and compiled WebAssembly cryptographic core. Keep all three from the same bundle together. | A reviewed Cinder SDK distribution supplied for your integration. |
| HTTPS origin (`baseUrl`) | The Cinder API service's scheme, hostname and optional port, without an endpoint path. It is not a Solana RPC or native venue URL. | Service connection configuration from the operator or integration maintainer. |
| Network and deployment IDs | Two nonzero 32-byte identifiers: one for the Cinder environment namespace, one for its logical deployment. They bind requests to the intended service. | Service configuration; they must match the server, not be generated by the client. |
| Manifest hash and PCR0/1/2 | The expected runtime configuration fingerprint and measurements of the enclave image, kernel/bootstrap and application. | An independently trusted release policy, not values accepted solely because the responding relay supplied them. |
| Private account ID | The identifier of your individual account in Cinder. It is neither your wallet address nor Cinder's pooled venue account. | Your existing account's setup information. Knowing this ID alone does not authorize access. |
| Policy version | The approved financial and precision policy revision for requests. It is not the SDK version or a user-selected leverage setting. | The applicable service/account configuration. |
| Current authority epoch | The account's current authorization generation. Revocation advances it and invalidates previous agent grants. | Current account configuration; refresh it when authorization changes. |
| Authentication lifetime | The maximum permitted validity window for a signed request, in milliseconds. It is not an order or position lifetime. | The authentication limit supplied for the service/account. The server enforces its configured maximum. |
| Wallet or agent signer | The owner wallet or authorized agent that signs Cinder messages locally. | Your wallet connection or agent key. Private keys remain with the signer. |

### API address

An illustrative origin is `https://api.cinder.example`, or `https://api.cinder.example:8443` if a custom port is configured. These are examples, not live service addresses. Supply only the origin: the SDK adds paths such as `/v1/attestation` itself. Non-root paths, query parameters, fragments and embedded credentials are rejected.

The API origin is distinct from your frontend application's origin, which the service may allow through its browser access configuration.

### Trust and authorization

The release policy answers **which service code to trust**. The account ID and signer answer **which account you may access**. Network and deployment IDs identify the intended Cinder environment; they are not numeric blockchain chain IDs or venue identifiers.

Expected release values must come from a trusted source independently of the relay being verified. The SDK compares the enclave's attestation with those expectations before sending private requests. A matching attestation identifies the approved release; it does not by itself establish that the software is error-free.

The authority epoch is separate from the policy version. If revocation advances an account from epoch `3` to `4`, subsequent requests must use `4`; the account ID stays the same. Revocation does not automatically cancel outstanding orders. See [agents](/guides/agents).

The example limits each request's authentication expiry to the earlier of the configured validity window and channel expiry. An order's `goodUntil` and an agent's grant expiry are separate deadlines; authentication expiry does not automatically close a position or cancel a resting order.

A signer exposes `publicKey: Uint8Array` (32 bytes) and `signMessage(bytes)`, returning a 64-byte Ed25519 signature. It never sends its private key to Cinder.

## Configuration example

Populate this application-defined configuration object with the inputs above. It is not an SDK export or an account-registration request. Replace every placeholder; there are no default service IDs, account IDs or authority values. Hashes and IDs are hexadecimal **without** a `0x` prefix.

```ts
interface IntegrationConfig {
  baseUrl: string;
  networkHex: string;
  deploymentHex: string;
  manifestHex: string;
  pcrHex: readonly [string, string, string];
  accountHex: string;
  policyVersion: string;
  accountEpoch: string;
  maximumAuthLifetimeMs: string;
}

const config: IntegrationConfig = {
  baseUrl: 'https://api.cinder.example', // Replace with the supplied API origin.
  networkHex: '<64 hex characters>',
  deploymentHex: '<64 hex characters>',
  manifestHex: '<64 hex characters>',
  pcrHex: ['<96 hex characters>', '<96 hex characters>', '<96 hex characters>'],
  accountHex: '<64 hex characters>',
  policyVersion: '<approved-policy-version>',
  accountEpoch: '<current-authority-epoch>',
  maximumAuthLifetimeMs: '<maximum-auth-lifetime-ms>',
};
```

The three integer fields are positive decimal strings. For example, `'60000'` means a 60-second authentication window, but is valid only if the configured service limit permits it. Do not assume that a policy version or authority epoch is always `'1'`.

## Connect and read

Use the interface and configuration above in this module, alongside the web SDK bundle.

```ts
import init, * as core from './channel.js';
import { connectWebChannel, PrivateClient, type MessageSigner } from './sdk.js';

function bytes(hex: string, length: number): Uint8Array {
  if (!new RegExp('^[0-9a-fA-F]{' + length * 2 + '}$').test(hex)) {
    throw new Error('Replace configuration placeholders with approved values');
  }
  const value = Uint8Array.from(hex.match(/../g)!, pair => parseInt(pair, 16));
  if (!value.some(byte => byte !== 0)) throw new Error('Zero ID or hash');
  return value;
}

function positive(value: string, maximum = (1n << 64n) - 1n): bigint {
  if (!/^[1-9][0-9]*$/.test(value)) throw new Error('Invalid configuration integer');
  const number = BigInt(value);
  if (number > maximum) throw new Error('Configuration integer out of range');
  return number;
}

export async function readAccount(
  config: IntegrationConfig, walletSigner: MessageSigner,
) {
  const network = bytes(config.networkHex, 32);
  const deployment = bytes(config.deploymentHex, 32);
  const account = bytes(config.accountHex, 32);
  const policyVersion = Number(positive(config.policyVersion, (1n << 32n) - 1n));
  const epoch = positive(config.accountEpoch);
  const authLifetime = positive(config.maximumAuthLifetimeMs);
  const policy = {
    network, deployment, manifest: bytes(config.manifestHex, 32),
    pcrs: [
      bytes(config.pcrHex[0], 48), bytes(config.pcrHex[1], 48),
      bytes(config.pcrHex[2], 48),
    ] as const,
  };

  await init();
  const channel = await connectWebChannel({ baseUrl: config.baseUrl, policy, core });
  try {
    const client = new PrivateClient(channel, walletSigner, {
      domain: { network, deployment }, account, policy: policyVersion,
    });
    const requestedExpiry = BigInt(Date.now()) + authLifetime;
    const expiresAt = requestedExpiry < channel.context().expiresAt
      ? requestedExpiry : channel.context().expiresAt;
    const result = await client.request({
      id: crypto.getRandomValues(new Uint8Array(32)),
      epoch, expiresAt, command: { kind: 'view' },
    });
    if (result.kind === 'error') throw new Error('Request returned ' + result.code);
    if (result.kind !== 'view') throw new Error('Unexpected response');
    return result;
  } finally {
    channel.close();
  }
}
```

Call `readAccount(config, walletSigner)` from your connected-wallet flow. With an authorized account and valid configuration, it returns a decoded value such as:

```ts Decoded account view
({
  kind: 'view',
  epoch: 1n,
  cash: 1000n,
  funding: 0n,
  held: 0n,
  positions: [],
  operations: [],
})
```

The amounts are illustrative quote atoms, not dollar balances. See [accounts](/guides/accounts) and [units](/api/units). An invalid placeholder fails before connection; an application error returns a code described in [errors](/api/errors).

## Continue with commands and subscriptions

The example closes its channel after one read. For a trading client, retain the verified channel for its valid lifetime and serialize requests. Add `transport: 'websocket'` to the connection options for socket commands and [subscriptions](/api/websocket).

Reference pages use `client` for this configured client and `ctx` for application-supplied request inputs:

| Input | Meaning |
| --- | --- |
| `id`, `epoch`, `expiresAt` | Request ID, current account epoch and authentication expiry. |
| `market` | Configured 32-byte market ID. |
| `goodUntil` | The command's financial deadline, separate from authentication expiry. |
| `originalOrderId`, `cancelAttemptId` | Original order request ID and distinct cancellation-attempt ID. |
| `agentPublicKey`, `agentExpiresAt` | Agent key and grant expiry. Import `READ`, `TRADE` and `CANCEL` from `sdk.js` for permission masks. |

In read examples, `Context` is an application-defined type with the fields above, not a type exported by the SDK. Import `ReadFamily` from `sdk.js` when using the generic paging example.

Decoded examples also use `recordedIntentDigest`, `snapshotRevision` and `quoteUnitId` for 32-byte values from their corresponding records, `observedAt` for a millisecond timestamp, and `approvedPolicyVersion` for the configured u32 policy. Examples show typed SDK values, not JSON to send over HTTP.
